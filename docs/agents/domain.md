# Domain docs

iTAG uses a single-context layout with `GLOSSARY.md` and `docs/adr/` at the project root.

- Before exploring the project, read `GLOSSARY.md` and any ADRs in `docs/adr/` relevant to the work. If either path is absent, continue.
- Use the glossary’s terms in specs, tickets, proposals, and tests. Bring missing terms to the `domain-modeling` skill when they need a decision.
- If a proposal conflicts with an ADR, cite the ADR and explain why its decision should be reopened.
- Create the glossary or an ADR through `domain-modeling` when the corresponding term or decision has been resolved.
